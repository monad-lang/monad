# Web and Oak

Monad's web profile compiles a program to a freestanding
`wasm32-unknown-unknown` module that a browser page instantiates with a small
JavaScript import object. The [Oak](#an-oak-spa) stack (`oak`, `oak_wasm`,
`oak_ui`, `web_wasm`) turns that into an Elm-shaped SPA: a pure
model/update/view, a diffing DOM runtime, and typed event handlers.

This chapter is the end-to-end guide the `web_wasm`/`oak` mote READMEs assume.
It is also the reference for the sharp edges an external consumer hits.

## The web profile

```bash
monad build --target wasm32-unknown-unknown app.mo -o app.wasm
```

The profile is **freestanding**: it links `-nostdlib`, imports only the JS
module `"monad"`, and needs **no sysroot**. A host `clang` with the wasm32
backend (and `wasm-ld`) is enough; `WASI_SDK_PATH` is only required for the
`wasm32-unknown-wasip1` profile. The web C compiler is `MONAD_WEB_CC` if set,
else the wasi-sdk clang when `WASI_SDK_PATH` is set, else host `clang`; a
nixpkgs *wrapped* clang needs `MONAD_WEB_CC=clang-unwrapped` (its hardening
flags are rejected by the wasm target). The output is a `.wasm` plus a JS
loader.

Four files make a deployable directory:

| File | Origin |
|---|---|
| `web.js` | Generated by `web_wasm::Glue.loader` from `WebAbi` (`scripts/gen-web-js.sh`). Build output, never committed. |
| `web_runtime.js` | Hand-written host: DOM, events, fetch, storage, WebCrypto, timers. Copy it beside `web.js`. |
| `app.wasm` | The compiled program. |
| `index.html` | Generated by `web_wasm::Shell.index_html` (a library call in your build script). |

There is no `monad web build` command: shell assembly is web tooling, so an
app's `[[script]]` produces the directory. See [Serving and
reload](#serving-and-reload).

## An Oak SPA

An app exposes three `#[export "c"]` thunks; the loader calls `oak_mount`
once, `oak_dispatch_event(id)` from each DOM listener, and `oak_tick` once
per animation frame.

```monad,ignore
#![mote { name := "counter", deps := [oak, oak_wasm, web_wasm, web_event] }]

use oak::typed {Oak.Node}
use oak::elements {Html.div, Html.button, Html.id_, Html.text}
use oak::events {Html.on_click}
use oak::app {Command, Host, Program}
use oak_wasm::program {Runtime.dispatch, Runtime.mount, Runtime.tick}

type Msg { increment }

def update (m : I64) (msg : Msg) : Pair I64 (Command Unit Msg) :=
    match msg { Msg.increment => Pair.pair (m + 1i64) Command.none }

def view (m : I64) : Oak.Node Msg :=
    Html.div [Html.id_ "app"]
        [Html.text (I64.to_string m),
            Html.button [Html.on_click Msg.increment] [Html.text "add"]]

def app : Program I64 Msg Unit := Program.app 0i64 update view
def host : Host IO Unit Msg := Host.host (fn _e => IO.pure Option.none)

#[export "c"] def oak_mount : IO Unit := Runtime.mount app
#[export "c"] def oak_dispatch_event (handler : I64) : IO Unit := Runtime.dispatch handler
#[export "c"] def oak_tick : IO Unit := Runtime.tick app host
def main : IO Unit := IO.pure unit
```

The page is tiny:

```html
<script type="module">
  import { start } from './web.js';
  start('./app.wasm', '#app');
</script>
```

## Commands, timers and focus

`Command` is `none`, `quit`, `dispatch`, `perform`, plus three runtime
commands:

- `Command.after ms msg` — one-shot `setTimeout`; the message stays in wasm
  and is delivered on the next tick. No interval, no per-frame render.
- `Command.focus selector` — applied **after** the patch, so a dialog
  inserted this frame can take focus (`autofocus` only works on page load).
- `Command.batch cmds` — left-to-right: effects run immediately, dispatches
  queue for the next batch, `quit` stops later commands.

`Subscription.window_filter event (WebEvent -> Option Msg)` ignores an
event when it returns `Option.none`: a `keydown` that only cares about
Escape should use it instead of re-rendering on every key.

## Handler ids and view shape

A handler id is an integer hash of the node's patch path and event name. It
is stable while the **view shape** is stable; inserting or removing siblings
changes later ids and the runtime replaces those listeners. For a changing
list, stamp children with `Html.key k`: a keyed list is reconciled by key, so
DOM nodes (and their listeners, focus and scroll) keep their identity.

## Subscriptions and the heap

The web allocator is a bump allocator and never frees. Exhaustion calls the
host's `oom` import (a `console.error` naming the sizes) and traps — not a
silent `0` or a negative-offset `RangeError`. `Memory.heap_bytes` /
`Memory.heap_used` expose committed/used bytes; a long session can persist
and `Window.reload`.

Avoid idle `Subscription.animation_frame`: each frame re-renders and
allocates. Prefer `Command.after` for a one-shot delay, and handlers only on
elements that can change.

## Browser surface (`web_wasm`)

| Module | What it gives you |
|---|---|
| `dom` | create/append/patch, attributes, listeners (flags `cdsopr`, `r` releases implicit touch capture), `element_at`/`attr` hit testing, `focus`, `query/value` |
| `event` | the live `WebEvent` snapshot: coordinates, modifiers, key, pointer, form value, drag/clipboard data |
| `fetch` | two-phase `begin`/`begin_with` (request headers), `poll`, `status`, `response_headers`, `read` |
| `storage` | `has`/`get_raw`/`get`/`set`/`remove`/`clear` (`get_raw` distinguishes absent from empty) |
| `clock` | `now_ms` (wall clock) and `monotonic_ms` (`performance.now`) |
| `media` | `matches query`, `watch`/`unwatch` for `matchMedia` changes |
| `crypto` | `random_bytes` (`getRandomValues`) and a two-phase SHA-256 |
| `window` / `memory` | `reload`/`navigate`, committed/used heap |
| `timer` | the `Command.after` bridge |

`Fetch.begin_with` and `Fetch.response_headers` carry headers as
length-prefixed blobs; that is what an authenticated API (bearer tokens,
`Content-Type`, DPoP nonces) needs.

## Serving and reload

Serving is a **script**, not a CLI verb. Add a `[[script]]` with
`[script-dependencies]` on `moon` (and `http`), then:

```monad,ignore
use moon::server {Server.serve_static}
use moon::static_files {StaticConfig, StaticConfig.default}
```

`Server.serve_static (StaticConfig.default "dist") "127.0.0.1" 8000u16` is a
fiber-per-connection static server (MIME types, ETags, ranges, traversal
guard). For live reload, `moon::Live` provides SSE plus a tree watcher, and
`monad script --watch` rebuilds and reruns the script when its tree changes.

## Debugging

- `Console.log` writes to the browser console.
- `fmt!`/`IO.println` write through the `write_stdout` import (the host's
  `console.log` outside Node).
- The Node harnesses in `wasm/web/*_smoke.mjs` drive the real runtime over a
  stub DOM; `scripts/check-wasm-target.sh` builds every fixture and runs
  them, so a broken extern/C/JS agreement fails before a browser is opened.
